# @red-cup-engineering/earning-loop-worker-service

A dependency-free Cloudflare Worker that runs an x402 seller's earning loops with no house machine in the loop.
It is parameterized by an Operations record. Coesite's is
`coesite-operations/operations-services-section`, `services/earning-loop-operations-services-section/data/earning-loops-operation.json`,
which also holds the runbook.

- **Settlement receiving** (`src/settlements.mjs`): lists the seller's settlement witnesses in R2 and
  corroborates each against two public Base providers. A witness counts only when both providers return the same
  successful receipt holding exactly one USDC transfer from payer to seller for the amount. This is the rule of
  original `@red-cup-engineering/x402-services-section/settlement-derivation/base-usdc-receipt` pure
  proof, not an independent ERC-20 matcher. The original Worker retains the separate side-effectful
  R2/RPC acquisition and payer classification. The exact source candidate is
  `0.13.8-dev.301`; this is held for independent immutable registry export, installed
  dependency and Workerd bundle receiving before release.
- **Buyability** (`src/route-health.mjs`): sends each listed offer the catalog's own example request and requires
  a 402 whose x402 challenge asks the catalog's exact amount in Base USDC. It tracks first-listed dates, held
  streaks and repair candidates, and can dispatch a repair to the seller's repository.
- **Self-adjusting prices** (`src/price-directives.mjs`, `src/border-price.mjs`): proposes raises, reverts and
  change-one-thing advisories from the border relation between ask and revealed bids. Directives close themselves
  when the live catalog shows their price. `scripts/apply-price-directives.mjs` applies pending ones to a catalog
  for its owner's release.
- **Scorecard** (`src/scorecard.mjs`): outside revenue, Group-payer revenue, buyers, revenue by route, buyable
  offers, and the mode against the operation's burn and goal.
- **On-chain hook** (`src/onchain-hook.mjs`): POSTs to an engine's scan endpoint each pass and keeps its answer.
- **Agent-market intelligence** (`src/agent-market-observation.mjs`): free, bounded, task-specific public x402 listings from 402 Index. The **existing** daily price-directives tick in `worker/earning-loops.mjs` reads only the exact Group Economic instance's `agentMarketIntelligence` selection and retains the previous R2 observation if the directory has no qualified page. Its `GET /agent-market-observation.json` is a read-only source observation, not a seller-advertised offer, buyer payment, guaranteed discovery, merchant authorization, customer lead or earnings. Buyer-market interpretation remains with the original 561 Group Opportunity provider; no ChatGPT subscription, app task, separate agent scheduler, self-purchase or outgoing payment is involved.
- **Clock** (`src/clock.mjs`): Workers cron triggers, or a self-re-arming Durable Object alarm when the account's
  cron allowance is spent.

```
npm test
CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN=… node scripts/deploy.mjs --operation <operation.json> --group-payers <addresses.json>
```

`data/operation.mjs` and `data/group-payers.mjs` are generated by the deploy. The committed copies mirror
Coesite's record so the tests run without it.

The deployment refuses an absent or malformed `merchantPayTo`; take the
recipient from the Group's current instance record, never from the quote under
test. Receipt amounts must be complete 32-byte ABI values. Conflicting provider
statuses remain retriable disagreements, and invalid witnesses spend no RPC
calls. Catalog HTTP failures preserve the prior route evidence. These checks
extend the existing receiver without changing its cash/delivery/acceptance
distinctions or its quarter-hour clock.

## Acquire prepared customer work

The original commercial operation selects up to three additional offers plus its
existing bid. The same singleton rotates one offer per commercial pulse; each
retains the twelve-provider-request and one-seller-mutation allocation, the original
seller credential and zero-new-cash ceiling. Each new task has separate private
state; the existing bid keeps its original state key.

Each offer pins its buyer, task description and updatedAt, price, prepared Public
product and conditional approach. Current actor-specific permission must permit
bidding on that exact agent-owned pitch. Complete own-bid inventory is read before
creation. Lost responses are reconciled without another creation. Changed scope,
human buyers and unsupported terms hold that offer. A received bid joins the existing
hire, machine agreement, native delivery and settlement flow. Public products may
specify an agreement with exact semantics and acceptance command; runtime never
executes buyer commands. Seven-day conditional bids establish no funded order or income.
