# Prepared issuer research in the existing earning loop

Requirements: the Group's researched issuer comparison operation needs one autonomous trusted producer, complete-cohort atomic cache replacement, retained prior evidence on source failure, persistent bounded Retry-After, and no customer-driven SEC egress. The issuer supplier owns acquisition, reconciliation, validation and provenance. This service only projects trusted operation data, calls its prepared-cohort export, and stores the complete returned object.

Behavior/design: optional `issuerResearch` is preserved verbatim only when explicitly enabled and its resourceAdmission.status is received, using the existing Durable Object alarm clock. A disabled/unreceived instance adds no producer work or cache writes. The original serialized EarningClock passes its own SQLite storage to the qualified two-key adapter, which validates prior cohort/status before calling the producer and atomically publishes staged complete cohort/status only after full success. Cohort and status use only `issuer-evidence/cohort` and `issuer-evidence/status`; both wrappers retain the exact configured logical cache key. No issuer cache/status/retry value is written through STATE/R2. Status survives directives/scorecard passes. Retry-After accepts HTTP delay seconds or an HTTP date without shortening; unrepresentable positive delays durably hold acquisition. Oversized status or transaction serialization durably holds with the specified sentinel while preserving the prior cohort; semantically corrupt status refuses. The existing coordinator retains its retry policy. Public readings and persisted last-run omit issuer status; only the internal run result retains it.

Resource allocation: for the initial two-issuer operation, three route probes and four existing settlement witnesses measured 38 external calls in an ordinary pass; the coincident weekly branch adds six, and alarm rearming adds one storage call (45 measured calls). Existing settlement STATE get + one LIST + four witness gets + sixteen RPC attempts + STATE put = 23; route STATE get + catalog get + three probes + STATE put = 6; scorecard three gets + two puts = 5; absent onchain hook one put; last-run one put; issuer source acquisition two SEC reads = 2. The issuer's SQLite reads and atomic writes stay inside the same object; actual storage/free-capacity admission is separate. Existing unrelated R2 maintenance remains. Repair dispatch and an attached onchain hook are disabled for this allocation. No third-party retry is added here. More issuers require fewer route probes. One settlement LIST page retains its continuation cursor only after all returned witnesses have been processed; reaching the end restarts the next scan so later arrivals and retryable witnesses remain eligible. The separate new issuer-only financial custody pass has its own between-maintenance allocation and is not admitted by these cache tests.

Private market consumption: one uniquely selected compiled issuer declaration supplies the same compute.configuration object to the qualified read adapter. It reaches the existing earning-loops singleton through a cross-script binding, accepts only its fixed logical cohort key, and exposes only get/body/size to the original supplier selector. The raw namespace is removed from the compute environment. The private GET precedes EarningClock's alarm-arming catchall and performs no alarm/status read or refresh. The public Worker never forwards it. The native edge transport uses manual redirects with explicit non-200 refusal; Workers rejects redirect:error at Request construction.

Construction: bounded caller/source normalization against the supplier's admitted prepared-cohort API, not a new semantic producer or workflow platform. Native esbuild bundles declared imports from the selected graph. Deployment uploads the resulting ESM artifact and keeps existing bindings/secrets, rather than maintaining an eleven-file upload whitelist. Build artifacts and standard esbuild metadata remain under source-owned worker-build records, keyed by input content.

Predesign receiving: test absent/unreceived config; full return before atomic write; prior cohort/status preservation on callback or transaction failure; numeric/date/greater-than24-hour/unrepresentable Retry-After and durable sentinel reentry; corruption/byte/transaction bounds; continuation over seen pages; exact private key/query/method and unchanged Unicode byte stream; no public cache/status/credential/alarm access; source-owned singleton/config selection and namespace pruning. Count the actual worst-case original four-provider/four-witness, three-route, two-issuer caller and coincident alarms. Native independent I/O and actual SQLite workerd private-binding tests are separate from generated pure-plan cases. Original supplier acquisition/paid-selector receiving, complete deployment closure, capacity and incremental-cost admission remain independently required before promotion.
