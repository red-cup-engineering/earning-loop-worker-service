# Prepared machine delivery

Original Work: [Opportunity 35](https://github.com/561-group/561-group-opportunity-services-section/issues/35). The operating requirement is a real external machine buyer, original reusable production, automatic delivery and separate payment evidence, with no human purchase/sale or new cash expense.

Group Economic owns task/bid/profile/price/payee and finite input limits. Public owns the product map, immutable artifact digest, original source and exact criterion evidence. This Engineering package consumes both; it owns neither the CSV producer nor credential recovery authority. Deploy compiles those records into parameter modules. Committed `data/products.mjs` is an empty reusable fixture.

Each private singleton Durable Object commercial pulse advances at most one provider effect, between existing maintenance pulses. Its client has twelve HTTP calls maximum, a finite seller-only endpoint allowlist, redirect refusal, shared OAuth DPoP, shared HTTP Retry-After and durable request keys. A first runtime seeds operational custody by signed key assertion, never a possibly consumed deployment refresh token. Rotating responses are persisted before use; uncertain refresh resumes by assertion. Explicit revocation/authorization denial stops credentials. Offline recovery keys never enter the Worker.

A matching real hire must receive the exact buyer-agent JSON agreement for the frozen product, contract snapshot, scalar behavior, finite input bound, automatic acceptance and buyer-funded settlement. Plain message instructions cannot execute code. Native REST eligibility plus a fresh actor/scope/endpoint-specific action gates delivery; this is distinct from hosted-MCP discovery, which autonomous DPoP does not authenticate. Drafts use expected versions; immutable revisions retain manifest digests. Unknown criteria, changed terms/payee, and unsupported requested changes hold. A refused effect retains its exact intent and requires changed provider authority/version before replay.

Provider documents: [authentication](https://opentask.ai/docs/agent-auth-integration), [delivery](https://opentask.ai/agent-docs/delivery), [hosted MCP](https://opentask.ai/docs/hosted-mcp), [current REST schemas](https://opentask.ai/api/openapi).

Buyer review, submission, acceptance, router-reported settlement and recognized outside income remain separate evidence. This seller never invokes buyer approval, payment creation or wallet execution. New commercial pulses use private DO storage only, without metered R2 operations. `/products.json` serves Public product metadata; `/commercial.json` exposes only stage, request count, zero new cash expense, observation and next-alarm times. No public route executes commercial work or reads private contracts/tokens.

Receiving cases cover no hire; strict buyer identity and JSON; complete prepared delivery; unknown criteria; substituted contracts/payees; optimistic concurrency and uncertain response readback; exact payment tuple; nonce and redirect refusal; terminal credentials; serialized alarms; request ceilings; durable Retry-After; no new commercial R2 operations. Parallel issuer preparation remains inactive unless its separate explicit enablement and resource admission are received.
