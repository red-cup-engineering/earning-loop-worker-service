# Prepared issuer research in the existing earning loop

Requirements: the Group's researched issuer comparison operation needs one autonomous trusted producer, complete-cohort atomic cache replacement, retained prior evidence on source failure, persistent bounded Retry-After, and no customer-driven SEC egress. The issuer supplier owns acquisition, reconciliation, validation and provenance. This service only projects trusted operation data, calls its prepared-cohort export, and stores the complete returned object.

Behavior/design: optional `issuerResearch` is preserved verbatim only when explicitly enabled and its resourceAdmission.status is received; a disabled/unreceived instance adds no producer step or new cache writes. Existing operations without it acquire no issuer data. A pass reads a dedicated issuer-research status register, honors `nextAttemptAt`, calls `prepareIssuerRevenueCohort(configuration)` once, then writes the returned complete object to the configured STATE cache key. No partial source data is stored. Status is separate from the serving cache and survives directives/scorecard passes. Retry-After accepts HTTP delay seconds or an HTTP date, retained without shortening; unrepresentable positive delays durably hold acquisition; absent/invalid values defer to the next ordinary pass. Successful refreshes also defer until the next ordinary pass. Only operational status is exposed through the existing readings interface.

Resource allocation: for the initial two-issuer operation, three route probes and four settlement witnesses give at most 41 Worker subrequests in an ordinary pass; the coincident weekly tick adds six, and alarm rearming adds one storage call (48 total measured calls): settlement STATE get + one LIST + four witness gets + sixteen RPC attempts + STATE put = 23; route STATE get + catalog get + three probes + STATE put = 6; scorecard three gets + two puts = 5; absent onchain hook one put; last-run one put; issuer status get + two SEC reads + complete cache put + status put = 5. Repair dispatch and an attached onchain hook are disabled for this allocation. No third-party retry is added here. Deploy projection refuses issuer instances exceeding this bound. More issuers require fewer route probes. The operation projection reserves six subrequests for a coincident weekly scorecard run. One settlement LIST page uses the witness limit and retains its opaque continuation cursor only after all returned witnesses have been processed; reaching the end restarts the next scan so later arrivals and retryable witnesses remain eligible.

Construction: bounded caller/source normalization against the supplier's admitted prepared-cohort API, not a new semantic producer or workflow platform. Native esbuild bundles declared imports from the selected graph. Deployment uploads the resulting ESM artifact and keeps existing bindings/secrets, rather than maintaining an eleven-file upload whitelist. Build artifacts and standard esbuild metadata remain under source-owned worker-build records, keyed by input content.

Predesign receiving: test absent optional config; full return before atomic write; source error preserves old cache; numeric/date/invalid/greater-than24-hour/unrepresentable Retry-After and next-tick suppression; continuation over seen pages without loss; deployment projection preserves all issuer fields and refuses over-budget combinations; count the actual worst-case four-provider/four-witness, three-route, two-issuer caller (41 per pass; 48 including the coincident weekly branch and alarm). Generated supplier tests independently qualify source acquisition semantics. No deployment or incremental-cost admission is asserted by these local tests.
